## Cursor Agent Bootstrap

The configured `.cursor/environment.json` start hook delegates to the importable Cursor bootstrap runner.  It accepts only `INFISICAL_TOKEN`, requires an explicit canonical folder, a nonsecret comma-separated `BOTFLEET_CURSOR_SECRET_NAMES` allowlist and a separately trusted `BOTFLEET_CURSOR_INFISICAL_ORIGIN`, and passes the declared names to the shared read-only raw fetcher.  These bindings come only from the process environment.  Project/environment/domain metadata is parsed as strict literal key/value data, with duplicate keys, unknown keys and shell syntax rejected; it is never sourced as shell code.  Any metadata domain must match the trusted canonical HTTPS origin, every request remains pinned there, and redirects are refused.  Names must be unique shell environment identifiers; every declared value must be available before output is published.  Undeclared folder values are excluded, and machine identity is never a fallback.  No tracked downstream consumer currently declares required names, so this source change supplies no default allowlist, origin or live binding.

Missing required bindings make no network request.  A versioned `BotFleet.manifest.json` receipt records the exact two active filenames, a scope fingerprint and their content hashes; current-UID regular non-symlink files must match it before deletion or replacement.  The directory must be 0700 and managed files 0600 before network or staging.  An exclusive lifecycle lock serializes overlapping hooks.  Old paths are atomically claimed into private quarantine and their moved inodes, modes and hashes checked; publication uses exclusive no-replace links with the manifest last.  Failed publication clears only matching newly published inodes and restores backups only into absent slots, retaining private recovery files when a concurrent edit prevents restoration.  Missing or rejected configuration removes only verified owned `~/.cursor-cloud-env/BotFleet.env` and `BotFleet.source.sh`, retaining the receipt.  Unmarked legacy outputs, user edits, invalid receipts, foreign ownership and symlinks are preserved and block bootstrap before network; they are never adopted automatically.  Successful output uses private staging and shell-safe quoting.  Other generated files are preserved, shell tracing is suppressed before credential access, and logs omit credential and fetched values.  Isolated fixtures exercise the actual configured hook without reading the real metadata file or contacting Infisical.

The Ubuntu Cursor workflow uses its existing Python3 capability only for a short-lived OS `flock` holder with an isolated interpreter and sanitized environment; no service or dependency installation is added.  The private lock inode is retained, while process death closes the pipe and releases the OS lock automatically.  Unexpected lock-helper exit blocks later network and mutation stages.  A private versioned journal records publication or invalidation intent and expected inode, mode, UID and hash metadata before active-path mutations, without credential or fetched values.  The next invocation reconciles only a dead process's exact journaled records under that lock; invalidation recovery finishes removal and never restores disabled values.  Live writers, unknown journals and edited recovery evidence stay unavailable.  The generated source helper validates a complete receipt under the same lock and returns verified snapshot bytes instead of blindly sourcing a pathname.  Child-process crash fixtures cover each enabled/off claim, off removal and publication link, and exceptions before or after each link leave no partially published active generation.

The canonical lock sentinel is exclusively created empty with mode 0600 and is never written, truncated or unlinked; the exact legacy ownership marker remains compatible.  No lock staging files are created.  Descriptor and pathname identity are checked before and after acquiring the OS lock.  Only fixed absolute interpreter candidates for Linux/macOS are considered, with root ownership and non-writable ancestors/symlink targets verified before execution.  The child receives only `LANG=C`, uses `-I -S`, and never searches inherited `PATH`; unavailable or untrusted interpreters fail closed.  The normal CI fixture asserts a trusted interpreter with `fcntl` is available on each supported host.

Recovery validates every existing transaction entry before changing any active pathname, then uses unique intermediate claim names.  It recognizes only exact generated disposal/intermediate names with matching journaled inode, hash, UID and mode metadata.  A uniquely disposed journal must pass the full owner, version, directory identity and dead-PID validation before use.  A single fully validated journal temp is eligible only while all active outputs still match its initial records; malformed, multiple or post-mutation temps remain untouched.  A matching prior journal must also validate before an off-intent temp can supersede it.  Empty private generated transaction directories can be retired; unknown or mismatched residue is preserved.  Real child-process fixtures also interrupt old/staged/journal disposal and invalidation recovery between rename and unlink.


## Managed Disable And Startup Bootstrap Boundaries

The managed backend checks the current enabled state before credential resolution, after source resolution or metadata/login completion, before each secret request and before returning read results.  A queued refresh re-enters the public refresh gate.  An upsert checks again between its PATCH and possible create-on-404 POST.  Already initiated work may finish before its next guard; a successful write that finishes after disable reports that it landed but could not be verified, preserving writeLanded instead of reporting an uncommitted mutation.  Isolated regressions cover these queue, login, metadata, read-result and write-stage interleavings.

The packaged Electron server-target bootstrap and managed shell token bootstrap are separate startup contracts outside the product connection toggle.  BF-2636 tracks an explicit local opt-in before those Keychain/helper/vault reads, with existing remote enrollments remaining fail-closed.  No startup source behavior, credential custody, runtime service or user installation is changed by this follow-up.
