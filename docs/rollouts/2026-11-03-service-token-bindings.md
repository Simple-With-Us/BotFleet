# Managed Service Token Bindings

BF-2622 changes source bindings only.  A read-only Actions metadata check confirmed the seven existing named read-token secrets; no credential value, runtime configuration, or registry entry was read or changed.  AFC-600 coordinates the live credential handoff.  Keep the currently running bootstrap and jobs intact until replacement bindings are approved, recorded, and verified; do not restart or switch a live process merely because these fixtures pass.

The repository has no `INFISICAL_VERCEL_CATCH_UP_READ_TOKEN` or direct `VERCEL_TOKEN` Actions secret.  Its token-only catch-up path must not be activated before the missing dedicated binding and reference scopes are verified.  Presence of the other secret names proves neither their validity nor their permissions.

Managed CI and the launch wrapper never authenticate a machine identity or fall back to Automation.  BotFleet's optional product machine identity choice remains available only after explicit selection in its backend settings.  A missing read token makes the managed fetch unavailable; existing same-name GitHub secret fallbacks remain available where callers already provide them.  Required missing values fail the job, and optional missing values warn.  The app still starts when Infisical is unconfigured.

Root `/` is one exact folder, not a recursive grant.  The CI fetcher sets `expandSecretReferences=false`, `include_imports=false`, and `recursive=false`, then rejects reference expressions anywhere in selected vault values or GitHub fallbacks.  An invalid vault value may use its existing valid same-name GitHub fallback; optional unavailable names warn, and required unavailable names fail.  It never follows a reference or chooses another folder automatically.

The pinned [v3 raw-list router](https://github.com/Infisical/infisical/blob/6a8bdfa882308e53e119b20c2b66a662c825e225/backend/src/server/routes/v3/deprecated-secret-router.ts#L238-L278) requires `secretValueHidden` and permits an omitted `secretPath`; its [base row schema](https://github.com/Infisical/infisical/blob/6a8bdfa882308e53e119b20c2b66a662c825e225/backend/src/server/routes/sanitizedSchemas.ts#L147-L174) requires string `workspace`, `environment`, `secretKey`, and `secretValue`.  The fetcher requires matching project/environment and `secretValueHidden=false`, and compares the exact folder when returned.  It does not invent mandatory folder provenance for the documented optional field.  Current public list documentation describes v4, so the pinned v3 contract governs this consumer.

Deployment version, live grants, and the presence of reference-backed CI values have not been checked.  Disabling expansion can make existing names unavailable where no valid literal same-name GitHub fallback exists.  PR #1551 stays held until replacement consumer paths are verified through AFC-600; passing these fixtures does not authorize a runtime switch, copying credentials, new token routes, or broader grants.  Read-only-only folders must stay off the write token, and a missing write token never borrows the read token or a machine identity.

The existing approved `fleet-secrets` bootstrap helper has its own authentication, which this patch neither inspects nor changes.  AFC-600 must verify that route as part of the live handoff; fetching only dedicated token names here does not prove the helper has stopped using Automation.

The one-way migration helper accepts dedicated primary-scope service tokens only.  Its dry run requires a read token, and `--apply` also requires a separate write token before any vault call.  It refuses matching source locators rather than borrowing the primary credential; use the app's scoped write-through path for that configured source.  This helper never creates credentials or updates the registry.

Run the isolated helper and workflow fixtures with `pnpm test:infisical-fetch`, `pnpm test:server-start`, and `node --test scripts/infisical-managed-auth.node-test.mjs scripts/ios-ship-workflow.node-test.mjs`.  These checks use fake credentials and temporary homes; they prove source behavior, not deployment or live access.
