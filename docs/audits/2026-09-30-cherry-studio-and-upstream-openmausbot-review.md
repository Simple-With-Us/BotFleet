## Scope And Method

Twelve parallel readers each took one slice (eight Cherry Studio dimensions: chat UX, providers and models, knowledge and memory, bots and code CLIs, MCP and tools, data and backup, platform ops, architecture and quality; four OMB slices: server and engines, product and mobile, infra and docs, and the Sep 24 leftovers).  Each reader proposed candidates with BotFleet evidence, and an adversarial verifier then re-checked every candidate against the BotFleet tree at 75568a850 and overrode the reader where the code said otherwise.  A critic then checked the draft for gaps, and a second round of six readers covered what the first round missed: OMB PRs in the delta that no row cited, OMB modules and verification docs, and four Cherry Studio areas (chat-app channel adapters, the stream and context pipeline, the job scheduler and data layer, and the non-chat renderer pages and file handling), each again checked by a verifier.  Across both rounds, 18 readers produced 481 candidates (321 from Cherry Studio, 160 from OMB); the verifiers marked 267 missing, 212 partial, 2 already present and 0 unverified.  After merging duplicates across readers the tables below hold about 360 rows, and the PR coverage appendix accounts for every upstream PR merged since Sep 24.  Findings marked "code-read" were established by reading the BotFleet source, not by running it: `node_modules` is absent from this worktree, so no unit test was run for this review. ## Executive Summary

1. **The cheapest wins are safety and correctness gaps, not features.**  Several S-sized items close real holes today: a failed send appears to eat the owner's prompt (code-read), auto mode will approve a write to `~/.zshrc` or a `git clean -fd`, a corrupt `bots.json` is silently overwritten with an empty roster, a broken `config.json` field silently runs the harness on defaults, a renderer crash leaves a dead window, and the iMessage lane has no stop word the model cannot miss and sends Linq replies without secret redaction.  Do these first; each is a day or less.
2. **Unattended work has no wall clock and loses half-finished output.**  A routine's "Maximum duration" is shown on its approval card but never enforced, so a turn that keeps streaming can run for hours; one queued run that throws inside the scheduler tick becomes an unhandled rejection that takes the harness down; and a turn stopped mid-reply drops the half-written text from the transcript and from the model's history.
3. **CI numbers are on the edge, and one cost figure is wrong.**  The Ubuntu CI test job peaked at 899 s against a 900 s cap and about 12 percent of recent main commits ended with a cancelled CI verdict because every push shares one concurrency group.  Claude turns are booked at the CLI's running total, which inflates per-bot cost rows and Usage Monitor figures; the rolling spend ceiling is not affected, because Claude CLI cost is tagged `estimated` and treated as unpriced (OMB has a tested fix, #1891).
4. **The biggest structural gap versus Cherry Studio is MCP as a client.**  BotFleet is an MCP server and mounts only its own tools, so Claude bots (strict MCP config) cannot use Playwright, Sentry, Postgres or any server the owner installs.  A user-managed MCP registry is the one large Cherry-inspired feature worth scheduling, and OMB's Apache-licensed `mcp-registry.ts` / `McpServersPanel.tsx` (#697, #956) is a portable starting point.
5. **Upstream OMB's best new ideas are about bots working together and remembering.**  The delegation ledger (hold a handoff for a busy peer instead of cancelling it), the stable/volatile prompt split for Codex and the ACP engines, per-bot auto recall over its own notes and past chats, a graceful Codex Stop, and the admission-decision refactor all address pains BotFleet's own audits already record.  Most of the Cloud, Pro, guest and Boat work upstream is multi-tenant and was skipped.
6. **Cherry Studio's chat-app channel layer is the richest second-round source.**  It routes reserved commands before the model, redacts every outbound message, and gates each message on a chat allowlist before any work (though an empty allowlist means allow-all, a default BotFleet's Linq lane shares and should drop).  Its job scheduler adds per-run deadlines and a three-strike failure breaker.  These map directly onto BotFleet's iMessage lane and routines.
7. **Much of Cherry Studio is polish BotFleet does not need.**  Region screenshots, mini apps, LAN transfer, Copilot sign-in, a local multi-dialect gateway and a full provider registry are large and mostly serve many-provider, many-user installs.  They stay in the tables for completeness with low value marked.

## Recommended Handful

Ordered for pick-up: quick safety wins first, then correctness, then the two structural bets.  All are verified missing or partial.  Items the verifier established by reading code only are marked "code-read": confirm each with a failing unit test before fixing.

   - What: keep composer text, attachments and reply target until the POST is accepted, and restore them if it is rejected or the harness is unreachable.
   - Why: the harness restarts often and a long prompt is lost today with no ghost message.
   - Size S.  Source: Cherry Studio (idea only).  Verified: code-read, not reproduced; confirm with a unit test.
   - Files: `src/state/store.tsx` (send action returns a promise), `src/components/Composer.tsx`, `src/lib/drafts.ts`, `src/components/GroupView.tsx`.

   - Why: in auto mode a single-stage command with no metacharacters is approved today, including writes to shell rc files and LaunchAgents.
   - Size S.  Source: Cherry Studio (idea only).  Verified: missing / partial.

   - Why: today every inbound text is a prompt, steered or queued, so an owner texting "stop" depends on the model noticing; and the Linq send at `server/index.ts:2625` and the push body built from `lastReply` take the raw event text although the stored row and the SSE copy are already scrubbed.
   - Size S.  Source: Cherry Studio (idea only; its adapters route `/new`, `/compact`, `/help` and `/whoami` before the model, while `/stop` is an idea from open Cherry issue #21016, not a Cherry behaviour).  Verified: partial (interrupt primitives exist) / partial (redaction on two of three egress paths).
   - Files: new `server/chat-commands.ts` and test, `server/index.ts` (messages route near `:10719`, `:2625`, `:2634`), `server/linq/outbound.ts`, `server/notify.ts`, `server/linq/outbound.test.ts`.
4. **Quarantine corrupt stores and warn when `config.json` is ignored** (`cherry-architecture-quality-7`, `cherry-data-backup-sync-9`, `omb-server-engines-27`, `omb-sep24-leftovers-27`, `gap-cherry-jobs-scheduler-and-data-layer-16`).
   - What: on a parse failure rename `bots.json` / `groups.json` / `routines.json` to `.corrupt-<epoch>`, refuse to save over them, show a banner; make `loadConfig` warn once with the file and the failing schema path, and salvage every section that still validates instead of dropping to defaults.
   - Why: a bad byte in `bots.json` becomes an empty roster that the next save makes permanent (audit A7). 5. **Supervise the main-window renderer** (`cherry-platform-ops-1`).
   - What: on `render-process-gone` reload the window once a minute at most, start `crashReporter` local-only, and log uncaught exceptions and rejections in main.
   - Why: a renderer crash is currently a blank window with no record, and the owner cannot tell a stuck UI from a stuck harness (audit D3, P1).
   - Size S.  Source: Cherry Studio (idea only).  Verified: missing.

6. **Make routines safe to leave unattended: a hard deadline and a tick that survives one bad run** (`gap-cherry-jobs-scheduler-and-data-layer-1`, `gap-cherry-jobs-scheduler-and-data-layer-17`).

   - Files: `server/routines.ts` (`tick()` around `:978-1165`, `failRun`, `:943-944`), `server/room-turn-timeout.ts` (reuse), `server/index.ts` (routine options), `server/routines.test.ts`.  Existing routines default to 30 minutes, so ship with a release note.

   - Why: the slowest Ubuntu run was 1 s under the 15-minute cap, and 7 of 60 recent main pushes ended cancelled.

## Keeping Up

One structural fact changed since Sep 24: `git merge-base origin/main upstream/main` now resolves to `677538eb8` (upstream, Aug 28), so BotFleet's history shares an ancestor with upstream again and `git cherry-pick <upstream sha>` can use ancestry.  The files have still diverged far, so expect conflicts on anything under `server/index.ts`, `src/components/Sidebar.tsx` or the drivers, and keep `git diff <a> <b> -- <path> | git apply -3` and re-implementation as the fallbacks.
