### #3791 Own-File Approval — Ported

Upstream #3791 (merge commit `267fa44f9fe4ea12f4645fa1185b2e55bdd6a2d9`) still applies to the native permission path: `AcpProcessRunner` answers ACP `session/request_permission` and `CodexAppServerRunner` answers Codex approval requests, both fail-closed through an injected handler, and neither had an own-file shortcut.  It is now ported as `NativeOwnFileReads` plus an opt-in `NativeOwnFileReadPolicy` (a data directory) on both runners.  A plain reading command (`cat`, `head`, `tail`, `grep`, `rg`, `sed -n 'N,Mp'`, `ls`, `wc`, `nl`, `stat`, plain or quoted words only, read-keeping flags only) or an ACP `read` call whose every path exists and resolves — symlinks followed — inside `workspaces/<bot>`, `task-workspaces/<bot>` or `bots/<bot>/SOUL.md` is answered without the handler.  Pipes, redirects, second commands, variables, globs, `grep -R`, `rg -L`/`--pre`, `tail -f`, `sed -i`, another bot's files, any other record-folder file, a missing file and a symlink out of the bot's folder still go to the handler.  Codex edits, `ask_user` and MCP elicitations are never shortcut.  A runner built without a policy is byte-for-byte the old fail-closed path, which is also how the upstream guest-turn exclusion maps: native `TurnInput` has no guest marker, so a composition that serves guest turns must not inject a policy.  The Claude runner has no permission broker to shortcut (it launches with `--permission-mode`), and the TypeScript server's own approval path is unchanged by this port.  No production composition constructs these runners with a policy yet — the same injected-interface status as the production mount provider above — so no live approval behavior changed.  Covered by `NativeOwnFileReadsTests` (plain-reader lexing, every non-plain shape, ACP read paths, and on-disk containment including the symlink escape).
