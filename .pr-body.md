## Why

The fleet repos moved to the `Simple-With-Us` org,  and BotFleet had the stale owner baked into places that actually run.

**A live bug,  found and fixed here.**  `VersionManifestFetcher.manifestURL` in `ios/Sources/CompanionCore/TestFlightUpdateCheck.swift` pointed at `https://jaywedgeworth22.github.io/ai-fleet-coordinator/ios-versions.json`,  which now returns **404**.  That is the shipped iOS TestFlight version check,  so every install was polling a dead URL.  The new path is `https://simple-with-us.github.io/AI-Fleet-Coordinator/ios-versions.json` and returns 200.  Note the new host is **case-sensitive** on the repo segment:  the lowercase form also 404s.

**Release publishing.**  `electron-builder.yml` `publish.owner` and `RELEASES_REPO` in `.github/workflows/release.yml` both still named the old owner,  so release assets would have been published against a path the org does not own.  The release workflow asserts `owner: ${RELEASES_REPO%%/*}` in the generated `app-update.yml`,  so the two had to move together.  The two runtime updater fallbacks in `scripts/after-pack.mjs` and `electron/updater.mjs` write the same owner and are updated to match.

**The clutch dependency.**  `package.json` now resolves `github:Simple-With-Us/Clutch`,  and `pnpm-lock.yaml` is regenerated with `--lockfile-only` so `--frozen-lockfile` in CI stays satisfied.  The regeneration changed only the clutch specifier and its tarball URL —  no other dependency moved.

## Two traps this avoids

- **Renamed,  not just transferred.**  `jaywedgeworth22/Harness` is now `Simple-With-Us/Clutch`,  and `jaywedgeworth22/agentic-trading` / `jaywedgeworth22/Socratic.Trade` are now `Simple-With-Us/Socratic-Trade`.  A plain owner swap leaves dead paths in every one of those spots.
- **Branch paths and user paths look like owner paths.**  The sweep is deliberately not a blind find-and-replace.  `scripts/audit-effort-board.mjs` parses PR links out of the effort log,  which is full of historical `jaywedgeworth22/BotFleet/pull/N` entries,  so its regex now accepts **both** owners rather than only the new one.  And the `server/webhooks.test.ts` / `server/webhook-payload.test.ts` GitHub **User-API** fixtures were reverted:  they model a person pushing,  and `api.github.com/users/<login>` is a user endpoint,  not a repo endpoint.
